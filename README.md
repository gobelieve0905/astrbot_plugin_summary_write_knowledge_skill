# 话题知识沉淀

独立 AstrBot 插件，将多人引用续聊中的结论保存成项目知识、规则或项目 Skill。复用现有知识库的嵌入与重排序模型，不更改现有模型配置。

当前为开发测试版 **0.1.1**，通过 develop 部署到既有服务器测试，尚未正式发布。

## 使用方式

在已登记的话题中引用消息并触发机器人：

> 把刚才确认的结论保存到 Idol Empire 的知识库，注明只适用于 AppLovin。

> 引用这条消息，把原来的测试标准更新成刚才讨论的新标准。

> 这是一个产品分析的新项目，名叫 Project B，为它建立资料并保存这些背景。

> 提取这个话题中的有效信息，形成长期方法论并保存。

Agent 读取话题与项目目录，整理内容，判断保存类型，并由当前聊天模型再次核验意图、项目和依据。明确的操作直接保存；项目、平台、结论或修改对象不明确时询问。普通“总结一下”不写入。

- **knowledge**：产品背景、事实、结论。
- **rule**：有适用条件的标准、约束。
- **skill**：含触发条件、输入、步骤、输出和边界的可重复方法。

成功回执包含项目、平台、知识编号、版本和来源覆盖范围。失败与超时不会返回成功状态，同一操作可重试。一次工具写入一个条目，多条成果分别返回状态。

## 安装与配置

要求 AstrBot **4.28.0 / 4.28.1**、Python **3.12+**、飞书内置 Agent，以及已经启用的引用续聊插件 `astrbot_plugin_quote_topics`（v1 绑定约定，基于 0.3.0 源码验证）。无需飞书卡片插件。

通过 AstrBot 后台“从文件安装”安装开发包，或在隔离测试环境将本目录放入 `data/plugins/astrbot_plugin_summary_write_knowledge_skill`。开发包不是市场发布包。

1. 确保 AstrBot 已有可用的知识库，其嵌入和重排序模型维持现有配置。
2. “可用知识库”留空表示全部库都可供选择；选择后仅使用指定库。下拉框支持搜索和多选，显示名称及 ID，保存 ID。配置键沿用 `template_kb`，旧名称文本自动兼容，唯一匹配时转换为 ID。
3. 打开 `enabled`。`group_ids`、`private_ids` 留空分别表示启用全部群聊、全部私聊；选择后仅启用对应列表中的会话。总开关默认关闭。
4. 在相同会话启用引用续聊；确保 Agent 可以使用本插件的四个工具。
5. 发送 `/知识管理状态` 检查配置，引用一段测试话题并要求保存，再查询验证。

已有项目优先使用同名知识库，也可以由用户明确指定目标库。首次保存会登记项目与库的对应关系，以后保持绑定。留空表示可选择全部库，不会将内容写进所有库，也不会按群名或发言人选库。

明确新建项目且没有对应库时，可以用项目名创建新库并复用现有模型。现有模型与分块配置有多套时会询问配置来源，不默认选择第一个库。填写了知识库范围时，只使用指定库，不擅自创建范围外的新库。

本插件检索仍按项目、适用平台和有效版本过滤。**原生知识库自动检索不经过插件的版本和权限过滤**，可能看到暂存索引；查询插件管理的规则应使用插件工具。历史 `chat-knowledge-…` 管理库仍按原绑定继续使用。

启用已有库不会批量接管旧文档。原有文档保留，本插件只对自己写入的条目管理版本；不要把“库已启用”理解为旧文档已迁移。

## 多人、多项目与共享

群内多位已授权成员可以共同保存和修改，`writer_ids` 可限制写入用户；留空表示已启用会话的全部成员。

群与用户身份仅用于**权限和来源**。项目由话题内容、明确指定或该话题已有绑定确定。同群可以有多个项目，多人可以讨论同一个项目。引用旧话题恢复旧话题归属，不沿用群里最近讨论的项目。

新项目默认仅创建它的会话可访问。跨群或私聊共享，在 `project_shares_json` 配置项目对应的会话范围列表；范围字符串通过 `/知识管理状态` 获取。配置示意：

```json
{"Idol Empire": ["复制另一个会话返回的完整范围字符串"]}
```

设置共享权限不会把这些群里的所有话题归入该项目。修改共享配置后重新加载插件。

## Skill 如何生效

Skill 保存为真实的 `SKILL.md`，与知识文档一样有项目、平台、版本、来源和检索索引。Agent 使用 `knowledge_read` 读取当前有效全文后，可以在当前任务中按步骤执行。

knowledge_save 不会安装到 AstrBot 全局技能目录，不会自动同步到沙箱，也不会执行生成的脚本。这样项目 A 的规则不会作为全局技能自动提供给项目 B。技能内容仍由模型理解执行，并非确定性程序。

## 版本与失败处理

更新前必须读取原条目，用知识编号和原版本更新。新文件与索引验证完成前，旧规则仍有效；旧文档清理成功后才确认保存；清理失败会保留待处理状态，重试继续核对，不会报告成功。原生库更新涉及多个步骤，处理期间不保证跨工具的原子可见性。

遇到“待处理”或索引失败，可引用原话题说“重试刚才的保存”。工具目录会提供原暂存计划，Agent 必须原样重试，避免重复建档。如果已有待处理版本且想改内容，先完成原写入再更新，不覆盖暂存文件。

若文件被外部修改、索引缺失、模型不可用、版本冲突或历史超出限制，插件明确失败。未来生效时间暂不支持；请在生效时更新。

## 来源范围与限制

- 当前读取 **AstrBot 已保存的话题历史**，并记录插件启用后观察到的请求消息身份、当前引用编号和完整来源快照。
- 未触发机器人的成员发言、安装前没有登记的引用、被删除的内容、未解析的附件，不保证进入话题记录。请让关键发言引用并触发机器人，或在最后明确补充缺失内容；插件不会声称总结了全群全部消息。
- 项目判断和内容核验使用当前聊天模型，额外消耗一次模型调用；无法保证模型判断永不出错。
- 仅支持一个 AstrBot 进程；不与其他程序同时编辑插件资料或管理库。原生后台手工修改不在版本事务范围内。
- 保存回执防护作用于最终模型响应；已经由平台流式发送的文本无法撤回。可靠结果以工具成功回执及后续查询为准。
- 为可靠过滤旧版本，检索在项目索引上限内取完整向量候选，再过滤有效版本和平台，最后复用原重排序模型。默认上限 5000 块，适合初期项目资料，不是无限容量方案。

## 数据与备份

数据保存在 `data/plugin_data/astrbot_plugin_summary_write_knowledge_skill/`：

- `knowledge.sqlite3`：项目、权限归属、话题绑定、版本和待处理操作。
- `projects/<项目编号>/<知识编号>/vN/knowledge.md` 或 `SKILL.md`。
- 同版本的 `topic.json`：保存时的来源快照，只留本地，不作为知识正文索引。

AstrBot 知识库目录保存实际索引。请一起备份 AstrBot 数据、插件数据和引用续聊数据。更新代码不能覆盖数据；恢复时需要成套恢复版本清单、文件和索引。

开发与隔离测试资料保留在仓库，源码归档会排除测试和开发文档。尚无 GitHub 仓库或市场上架地址。

### 范围下拉框

平台实例、群聊、私聊、写入用户、知识库均支持搜索多选，清空选择表示全部。平台和知识库直接读取 AstrBot；群聊读取飞书机器人可见群，用户读取可见群成员和已知用户记录，不代表企业全部通讯录。候选每 5 分钟刷新，重新打开配置页查看。权限不足或网络异常时保留已知候选和原有选择，并显示提示；仅保存名称与 ID 等身份目录信息，不缓存聊天正文。

## 原生技能读取与长话题入库

无需打开 Computer Use，Agent 可调用 `native_skill_list` 列出当前配置及人格允许的已启用本地技能，再用 `native_skill_read` 读取 `SKILL.md` 及技能目录内的配套文本、脚本源码。长文本按 `next_offset` 分页读完；该读取工具不会执行脚本或开放任意宿主路径。该能力受本插件总开关与会话范围约束，不要求话题绑定；知识写入仍要求引用续聊绑定。

`max_topic_chars` 现在是单次整理范围上限。短话题仍完整读取；长话题返回带角色、摘要、长度和快照指纹的来源目录。Agent 先调用 `knowledge_source_read` 分页读取，再用 `knowledge_source_select` 指定已读片段及选择依据。当前消息由来源 `current` 表示；当前消息中由飞书适配器下载到临时目录的 Markdown/TXT 附件也可作为来源，单文件最多 1 MiB。旧附件若没有出现在目录中，需要重新附上或粘贴正文，不能仅凭文件名保存。

可在原话题说：“只把我这次附上的项目资料保存到指定项目知识库，仅适用于 Meta；不要把整段查询日志作为正文。”项目未确定时仍需询问。若要求整理整个话题，Agent 不能擅自只选尾部消息，应明确分段范围或请用户澄清。

所选内容和原始保存请求一起交给独立模型校验，完整来源快照另外保存在 `source-snapshots/<指纹>.json`，不加入检索索引。保存回执注明局部范围，不宣称覆盖未读取的历史；只有文件、版本记录和索引验证成功才确认已保存。

### 0.1.0 团队 Skill

成员在已启用会话引用已确认内容，例如：

> 将这个流程安装为团队 Skill，分类为数据查询，适用于 Meta 所有项目，团队共享。

> 将这个方法保存为 Idol Empire 项目 Skill，供项目成员使用。

`native_skill_install` 保留工具名兼容，但 0.1.0 写入插件管理的团队技能目录与 SQLite 版本库，不再写 AstrBot 全局技能文件目录。所有满足插件写入范围的成员都可以创建，默认仅个人可见，无需 AstrBot 管理员。原生内置技能继续使用原有权限和界面。

- 分类方便查找；平台和项目限制实际使用。共享分为个人、项目、团队。团队指同一平台实例和机器人内的已启用会话，不跨机器人自动共享。
- 项目访问继续沿用已有项目的会话访问范围及跨会话共享配置；它只授予访问权限，不决定当前话题的项目。
- 创建人和指定维护者可以更新；共享范围及维护者仅创建人和管理员可改。其他可见成员可以提出修改建议和反馈，不能覆盖别人的内容。管理员可管理全部团队 Skill。
- 当前支持自包含的 SKILL.md。项目专用流程可以保存并注明项目，账户映射、事实和数据仍存知识库。安装不增加工具、账户或代码执行权限。
- 开始任务先按平台和项目查目录，再读完整 Skill。读取后固定本轮版本，更新不打断已开始的读取；停用或撤销权限立即阻止后续读取，但已经送给模型的内容无法收回。
- 更新使用版本号和正文指纹防止覆盖。旧版保留但不默认使用；回滚产生新版本，保留当前共享范围。失败无成功回执。

后台「插件页面 → 团队知识与技能」提供分类/平台/项目/共享/状态筛选、正文、分组与维护者设置、启停、回滚和建议反馈。管理页使用 AstrBot 后台登录权限，普通成员通过聊天操作自己的技能，无需给予后台管理员权限。

`native_skill_list` 同时列出可访问团队技能和允许的原生技能；团队技能以稳定 id 区分同名内容。`native_skill_read` 在每次读取时校验共享、平台和项目；`team_skill_manage` 支持版本、启停、回滚、建议和反馈。知识检索仍复用已有嵌入和重排序模型；Skill 使用可筛选目录发现，再整篇读取，不切碎规则。

### 附件与任务成果

插件会缓存当前话题已经实际读取的 Markdown/TXT 附件（每话题保留最近 30 份），引用旧话题时可复用，按会话和话题隔离。缓存从升级后开始积累，不会凭空补回从未读取的旧文件。

若内容来自代码执行插件的结果文件，Agent 可用 `knowledge_artifact_import` 读取话题中真实任务 ID 对应的 Markdown/TXT，再选择和保存，不重新运行代码。该入口沿用代码插件原有文件所有者权限；文件过期、属于别人或没有权限时仍需有权限的成员发送附件。

### 升级与测试

升级保留原知识库、插件配置和历史原生技能。旧版安装到全局目录的文件不自动搬迁或改变权限；新创建内容出现在团队管理页。当前版本通过 develop 部署测试，未合并 main、未打标签。

先让两位成员验证个人隔离、团队共用和不能覆盖他人技能，再测试更新、回滚及另一个项目使用通用 Meta 方法。成功保存不保证模型每次都会选中；请检查回复中的技能名称/版本及实际工具调用。

### 0.1.1 成果登记与分别保存

> 将这次方法保存为 Meta 团队 Skill，并将项目资料写入 Idol Empire 知识库。

插件读取当前和引用消息中已下载的文本附件；代码任务启动/查询完成时登记任务与话题，并在后台取回最多 25 个 Markdown/TXT 文件（每文件不超过 1 MiB），不运行查询、不读取其他用户的任务。原任务过期后，已成功登记的正文仍可通过本人原话题取回。升级前没有登记的任务仍可按原任务权限导入；已过期且没有缓存的文件不能恢复。

`knowledge_context` 同时提供成果目录和最近保存进度。`knowledge_artifact_import` 先查本人缓存，再尝试原任务。自动取回的文件缓存仅本人可读；群内已经发送的附件仍按原话题可见性处理。进入项目知识库或团队 Skill 必须另行通过原有意图与范围校验。

Agent 用 `knowledge_delivery` 提交 skill / knowledge 两部分，分别执行校验、存储及知识索引验证。每部分独立回执；其中一部分失败不会撤销另一部分。返回 delivery_id 后，可用同一 ID 继续，仅执行未成功的部分；可补充未完成部分的修正计划，禁止改写已成功部分。不会自动重新生成 Skill 或重新调用查询 API。原发起人、原会话及原话题才能继续，防止引用别人的任务扩权。

后台管理页可查看最近的保存进度。任务成果读取失败会说明缓存、过期或权限情况，再请求引用原文件或补发。查询缺项目资料时，应先让用户选择补资料或明确限定账户范围；历史数字标日期，账户映射需核对，失败不能记为零。该行为由 Agent 遵循提示，真实业务执行仍需验收，插件不硬编码 Meta 查询逻辑。

## 0.1.1 原生库接入与保存进度修复

- 原生知识库直接按名称或 ID 检索，无需先登记插件项目或重复导入。原生文档会标注“平台待确认”，Agent 阅读全部索引文本后判断适用范围；索引文本可能有重叠，不冒充原附件。
- 替换原生旧文档时先读取并核对指纹，归档旧索引正文；新文档索引验证及旧文档删除完成后才确认成功。替换须明确针对整个文档，不能拿局部结论覆盖整篇资料。
- 首次写入已有原生库不把它锁给首个群聊；仍遵守可用库范围及明确配置的项目共享限制。新建项目保留原有会话共享机制。
- 保存超过 15 秒返回任务编号，使用 `knowledge_save_status` 查询进度。调用方超时不取消后台任务；后台模型校验仍有超时上限。仅 `saved` 表示成功。
- 同一用户、同一话题、同一计划重试复用任务和暂存版本。失败或服务重载后的任务保留状态及原计划；需明确重试，不会在重启后自动重新调用模型。变更计划不算同一次重试。

日常可以说：“查看刚才保存的进度”；失败后说：“按原计划继续刚才的保存”。项目不明确仍会询问。知识仍写入 AstrBot 原生库；团队 Skill 由插件分组和管理，不会自动变成全局技能。


### 知识审核说明

保存前的审核是插件额外调用当前聊天模型，不是后台人工审批。审核会收到完整选定来源、保存计划和本轮通过工具读到的旧文档正文；不会只告诉模型“读过”。无关项目目录与重试计划不重复送审。

知识审核使用独立配置 `knowledge_review_timeout`，默认 300 秒；原 `review_timeout` 保留给技能校验。仍在处理时查询任务状态即可。超时仍明确失败，不会跳过来源和项目检查，也不代表已经写入。增加等待上限不保证外部模型永不超时。
