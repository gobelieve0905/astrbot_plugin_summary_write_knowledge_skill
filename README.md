# 话题知识沉淀

独立 AstrBot 插件，将多人引用续聊中的结论保存成项目知识、规则或项目 Skill。复用现有知识库的嵌入与重排序模型，不更改现有模型配置。

当前为开发版 **0.0.0**，尚未发布或部署到生产。

## 使用方式

在已登记的话题中引用消息并触发机器人：

> 把刚才确认的结论保存到 Idol Empire 的知识库，注明只适用于 AppLovin。

> 引用这条消息，把原来的测试标准更新成刚才讨论的新标准。

> 这是一个产品分析的新项目，名叫 Project B，为它建立资料并保存这些背景。

> 提取这个话题中的有效信息，形成长期方法论并保存。

Agent 读取话题与项目目录，整理内容，判断保存类型，并由当前聊天模型再次核验意图、项目和依据。明确的操作直接保存；项目、平台、结论或修改对象不明确时询问。普通“总结一下”不写入。

- **knowledge**：产品背景、事实、结论。
- **rule**：有适用条件的标准、约束。
- **skill**：含触发条件、输入、步骤、输出和边界的可重复方法。

成功回执包含项目、平台、知识编号、版本和来源覆盖范围。失败与超时不会返回成功状态，同一操作可重试。一次工具写入一个条目，多条成果分别返回状态。

## 安装与配置

要求 AstrBot **4.28.0**、Python **3.12+**、飞书内置 Agent，以及已经启用的引用续聊插件 `astrbot_plugin_quote_topics`（v1 绑定约定，基于 0.3.0 源码验证）。无需飞书卡片插件。

通过 AstrBot 后台“从文件安装”安装开发包，或在隔离测试环境将本目录放入 `data/plugins/astrbot_plugin_summary_write_knowledge_skill`。开发包不是市场发布包。

1. 在 AstrBot 创建或选择一个已经可用的知识库，其嵌入和重排序模型维持现有配置。
2. 设置本插件的 `template_kb` 为这个库的名称或 ID。它只提供模型和分块配置，不自动复制或修改原资料。
3. 打开 `enabled`。`group_ids`、`private_ids` 留空分别表示启用全部群聊、全部私聊；填写后仅启用对应列表中的会话。总开关默认关闭。
4. 在相同会话启用引用续聊；确保 Agent 可以使用本插件的四个工具。
5. 发送 `/知识管理状态` 检查配置，引用一段测试话题并要求保存，再查询验证。

每个明确项目首次创建自己的 `chat-knowledge-…` 管理库，内容文件位于插件数据目录。首次保存到尚未登记的项目可能需要确认建立项目资料。

**不要把 `chat-knowledge-…` 库加入 AstrBot 全局或会话原生知识库列表。** 本插件的检索工具负责有效版本、平台和会话权限过滤；原生知识库直接检索会绕过这些约束，也可能看到待处理索引。

已有原生库仍可按原方式使用。本版不会自动接管或覆盖原生库里的旧文档；需要先明确迁移对应资料，再由本插件管理后续版本。`template_kb` 不是旧资料自动迁移开关。

## 多人、多项目与共享

群内多位已授权成员可以共同保存和修改，`writer_ids` 可限制写入用户；留空表示已启用会话的全部成员。

群与用户身份仅用于**权限和来源**。项目由话题内容、明确指定或该话题已有绑定确定。同群可以有多个项目，多人可以讨论同一个项目。引用旧话题恢复旧话题归属，不沿用群里最近讨论的项目。

新项目默认仅创建它的会话可访问。跨群或私聊共享，在 `project_shares_json` 配置项目对应的会话范围列表；范围字符串通过 `/知识管理状态` 获取。配置示意：

```json
{"Idol Empire": ["复制另一个会话返回的完整范围字符串"]}
```

设置共享权限不会把这些群里的所有话题归入该项目。修改共享配置后重新加载插件。

## Skill 如何生效

Skill 保存为真实的 `SKILL.md`，与知识文档一样有项目、平台、版本、来源和检索索引。Agent 使用 `knowledge_read` 读取当前有效全文后，可以在当前任务中按步骤执行。

它不会安装到 AstrBot 全局技能目录，不会自动同步到沙箱，也不会执行生成的脚本。这样项目 A 的规则不会作为全局技能自动提供给项目 B。技能内容仍由模型理解执行，并非确定性程序。

## 版本与失败处理

更新前必须读取原条目，用知识编号和原版本更新。新文件与索引验证完成前，旧规则仍有效；切换后旧版本仅保留本地历史，旧索引尽力清除，即使清除失败也不会经本插件检索返回。

遇到“待处理”或索引失败，可引用原话题说“重试刚才的保存”。工具目录会提供原暂存计划，Agent 必须原样重试，避免重复建档。如果已有待处理版本且想改内容，先完成原写入再更新，不覆盖暂存文件。

若文件被外部修改、索引缺失、模型不可用、版本冲突或历史超出限制，插件明确失败。未来生效时间暂不支持；请在生效时更新。

## 来源范围与限制

- 当前读取 **AstrBot 已保存的话题历史**，并记录插件启用后观察到的请求消息身份、当前引用编号和完整来源快照。
- 未触发机器人的成员发言、安装前没有登记的引用、被删除的内容、未解析的附件，不保证进入话题记录。请让关键发言引用并触发机器人，或在最后明确补充缺失内容；插件不会声称总结了全群全部消息。
- 项目判断和内容核验使用当前聊天模型，额外消耗一次模型调用；无法保证模型判断永不出错。
- 仅支持一个 AstrBot 进程；不与其他程序同时编辑插件资料或管理库。原生后台手工修改不在版本事务范围内。
- 保存回执防护作用于最终模型响应；已经由平台流式发送的文本无法撤回。可靠结果以工具成功回执及后续查询为准。
- 为可靠过滤旧版本，检索在项目索引上限内取完整向量候选，再过滤有效版本和平台，最后复用原重排序模型。默认上限 5000 块，适合初期项目资料，不是无限容量方案。

## 数据与备份

数据保存在 `data/plugin_data/astrbot_plugin_summary_write_knowledge_skill/`：

- `knowledge.sqlite3`：项目、权限归属、话题绑定、版本和待处理操作。
- `projects/<项目编号>/<知识编号>/vN/knowledge.md` 或 `SKILL.md`。
- 同版本的 `topic.json`：保存时的来源快照，只留本地，不作为知识正文索引。

AstrBot 知识库目录保存实际索引。请一起备份 AstrBot 数据、插件数据和引用续聊数据。更新代码不能覆盖数据；恢复时需要成套恢复版本清单、文件和索引。

开发与隔离测试资料保留在仓库，源码归档会排除测试和开发文档。尚无 GitHub 仓库或市场上架地址。
